# ORB-SLAM3 Stereo-Inertial — Orbbec Ego (Stage 3)

Goal: compute per-frame **camera 6DoF poses** from stereo + IMU, so we can lift
the camera-frame hand data (`hands_3d_pose.json`) into a **fixed world frame**.

Environment: **Apple M3, arm64-native Docker** (no emulation). Docker VM set to
**6 GB** for the build. ORB-SLAM3 is CPU-bound — no GPU needed.

## Steps

```bash
cd stereo_3d/orbbec/slam3

# 3b-1: build the image (one-time, ~30-45 min, cached after)
./build.sh                 # JOBS=4 default; JOBS=2 ./build.sh if OOM

# 3b-2: GATE — prove the build on a public EuRoC sample (~1.4 GB download)
./run_euroc_test.sh        # must print a multi-row trajectory

# 3c: run on OUR clip (after reviewing the settings YAML — see below)
./run_orbbec.sh            # -> stereo_3d/slam_out/f_orbbec_traj.txt
```

## ⚠️ Settings to VERIFY before trusting a run on our data
The DRAFT settings (`stereo_3d/slam_data/orbslam3_stereo_inertial_DRAFT.yaml`)
were auto-generated by `slam_prep.py`. Two items are flagged and MUST be checked
against ORB-SLAM3's own fisheye example (`Examples/Stereo-Inertial/*.yaml`):

1. **`IMU.T_b_c1` convention/sign.** Provider gives `T_cam_imu` (imu->cam). We
   emit its inverse as body->cam. Confirm ORB-SLAM3's expected direction for
   this version; a wrong transform silently corrupts the fusion.
2. **Stereo `lapping` / overlap columns** for the KannalaBrandt8 stereo model —
   the auto-draft omits these; copy the structure from the reference fisheye
   YAML and set the overlap region for our 1600x1300 images.

Also sanity: `IMU.Frequency` — actual median rate is ~999 Hz (we set 1000).

## Data layout consumed
`stereo_3d/slam_data/` (EuRoC/ASL), produced + validated by `slam_prep.py`:
```
cam0/data/<ts_ns>.png   cam0/data.csv     # left  (3587 frames)
cam1/data/<ts_ns>.png   cam1/data.csv     # right
imu0/data.csv                             # ts_ns, wx,wy,wz, ax,ay,az (999 Hz)
timestamps.txt                            # one ts_ns per stereo frame
frame_map.csv                             # ts_ns -> ORIGINAL video frame_idx
```
`frame_map.csv` is how we map SLAM poses back to `hands_3d*.json` frames
(remember: frame 0 trimmed to the IMU span; video ended at frame 3587).

## Honesty / caveats
- Camera model: we feed **KB fisheye** (from `calibration_camera.yaml`). The
  provider's `T_cam_imu` was Kalibr-fit against a Brown/rational model, but the
  intrinsics agree to ~1px and the extrinsic is model-independent — treated as a
  validated assumption, not a given.
- The **timeshift sign** (−13.49 ms) is baked into camera timestamps but is
  below offline-verifiable resolution. Final proof is the Stage-3d test:
  **a hand held still must stay put in WORLD coords while the head moves.**
- Watch Stage 3c for: inertial-init success, gravity alignment, and
  tracking-lost gaps over the **shiny metal table** (low texture = ORB-starved;
  IMU should bridge short gaps).
